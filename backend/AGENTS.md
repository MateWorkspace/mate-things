# Project Context

This is the Go API + MQTT service for `mate-things`, an IoT fleet-management
platform for ESP32-class devices (device registration, firmware OTA, action
dispatch, telemetry, node logs, RBAC, infrared capture/replay — see the
repo-root `AGENTS.md` for what the product actually does and how this
service fits alongside `frontend/`). This backend is the authority for
every business rule, permission check, and device-protocol contract; the
Next.js frontend is a pure client of its REST API and owns no business
logic of its own.

Module: `github.com/MateWorkspace/mate-things/backend`. Stack: Go, Echo
v5 (HTTP), paho (MQTT), pgx + squirrel (Postgres), go-redis (cache),
MinIO SDK (firmware storage), golang-migrate (schema), goja (JS execution
for infrared encoders), zerolog/slog (logging), swaggo (`swag`) for API
docs.

# Project Structure

Layered/clean architecture with a strict, one-directional dependency rule:

```
presentation → application → domain ← infrastructure
                                ↑
                          composition (wires everything together)
```

`domain` depends on nothing else in this module. `application` and
`infrastructure` both depend only on `domain` (never on each other
directly). `presentation` depends on `application`'s usecase interfaces
(never on `infrastructure` directly). `composition` is the only place
allowed to import concrete types from every layer at once, to construct
and wire them together.

```
backend/
├── cmd/
│   ├── main/            API+MQTT binary entrypoint — compositionmain.Launch()
│   └── seeder/          one-shot DB seeder binary — compositionseeder.Launch()
├── internal/
│   ├── domain/          contracts, models, usecase interfaces — no deps
│   ├── application/     usecase implementations — business logic + validation
│   ├── infrastructure/  concrete adapters for every domain contract
│   ├── presentation/    HTTP (Echo) + MQTT (paho) handlers, routes, DTOs
│   ├── composition/     dependency wiring only, no business logic
│   └── config/          all BE_* env vars, loaded once at process start
├── database/
│   ├── migrations/      golang-migrate SQL, timestamp-prefixed
│   └── seeder/          baseline RBAC + example data, embedded via go:embed
├── docs/
│   ├── swagger/         generated by `swag init` — never hand-edit
│   ├── agent_test/      manual/scripted end-to-end test checklists per release
│   └── releases/        release notes
└── pkg/
    └── pgxdt/           standalone pgx transaction-context helper
```

## `internal/domain/`

The core layer. Contains no framework/driver imports (no pgx, no Echo, no
paho) — only Go stdlib, `github.com/google/uuid`, and similar
dependency-free packages.

- **`models/`** — plain structs and enums shared across layers (`Node`,
  `Firmware`, `PayloadSchema`, `NodeLog`, `InfraredRecordSessionEvent`,
  `LlmClientStatus`, `NodeStatus`, ...) plus the shared `Error` type (see
  [Error handling](#error-handling) below). Small status/enum types live
  here even when only one contract's method returns them — they are never
  nested inside a `contracts/` package.
- **`contracts/`** — interfaces the application layer depends on and
  infrastructure implements, one subpackage per concern:
  - `repository/` — one interface per Postgres-backed entity.
  - `cache/` — Redis-backed decorator interfaces mirrored 1:1 against
    `repocache` usecases (see below).
  - `storage/` — firmware binaries via MinIO.
  - `node/` — MQTT publish/subscribe.
  - `broadcaster/` — per-domain-typed live websocket fan-out (`Telemetry`,
    `InfraredRecordSession`).
  - `llm/` — `Client` (stateless `GenerateText(ctx, req) (result, error)`
    only — no `Connect`/`Disconnect`/`Status`; this was deliberately tried
    and reverted, see [LLM client shape](#llm-client-shape)) and
    `ClientFactory` (`Current(ctx) (Client, error)` — resolves the
    currently-configured provider/model and returns an already-usable
    client).
  - `utility/` — password hashing, JWT tokens, API key generation/hashing,
    payload-schema validation, `JSEngine` (runs generated encoder JS via
    goja), encryption (for at-rest secrets like the LLM API key).
  - `logger/` — the `Leveled` logging contract.
- **`usecases/`** — one interface per feature area (`admin`, `node`,
  `node_log`, `action`, `auth`, `profile`, `preferences`, `telemetry`,
  `infrared`, `seeder`), plus their request/response DTOs. Also includes an
  internal `repocache/` interface set — a second, narrower usecase-shaped
  contract used only by the cache-decorator layer (see below).

## `internal/application/`

One package per usecase interface (e.g.
`application/admin/user_management/`, `application/infrared/
record_session_management/`), implementing the business logic:
orchestrates repositories/contracts and owns **value validation** (see
[Validation convention](#validation-convention)).

- `application/shared/` — reusable value-validation helpers
  (`RequiredUsername`, `RequiredPersonName`,
  `RequiredPayloadSchemaDefinition`, etc.), paired `Required*`/`Optional*`
  per field.
- `application/repocache/` — a Redis-backed caching decorator sitting in
  front of the raw Postgres repositories, implementing the domain-side
  `repocache` usecase interfaces. Callers elsewhere in `application/`
  depend on `domainusecasesrepocache.*` instead of
  `domaincontractsrepository.*` directly whenever a cached read path
  exists; write paths still go through the interface's own
  invalidation logic, not straight to the repository.
- Feature areas with multi-step orchestration split further, e.g.
  `application/infrared/` has separate packages for `record_session_
  management` (drives the recording state machine), `case_generation`,
  `coder_generation`, `analysis`, and `reference_management` — each a
  distinct usecase interface rather than one monolithic infrared usecase.

## `internal/infrastructure/`

Concrete implementations of domain contracts, one subpackage per
contract-family, generally one-directory-per-entity/driver:

- `repository/` — Postgres via squirrel (query building) + pgx (driver),
  one package per entity (`repository/node/`, `repository/infrared_
  record_session/`, ...).
- `cache/` — Redis, mirrors `repository/`'s entity split.
- `storage/firmware/` — MinIO, presigned upload/download URLs.
- `node/publish/` + `node/subscriptions/` — MQTT via paho.
- `utility/` — `password/` (bcrypt), `token/` (JWT), `apikey/`
  (generation/hashing), `payload_schema_validator/` (hand-rolled),
  `encryption/` (AES-GCM, used to encrypt the LLM API key at rest),
  `jsengine/` (goja-based JS encoder runner — implements
  `domaincontractsutility.JSEngine`).
- `llm/client/` — one file per provider SDK adapter (`claude.go`,
  `openai.go`), package `infrastructurellmclient`, each exposing a
  `New<Provider>Client(...) domaincontractsllm.Client` constructor. Purely
  stateless request/response wrappers around the provider's Go SDK — no
  local connection state.
- `llm/client_factory/` — owns the `LlmConfig` repository dependency and
  the `Encryptor`, decrypts the stored API key, and switches on the
  configured provider to construct the right `llm/client` adapter. This is
  why the repository lives inside infrastructure here rather than being
  reached from the application layer directly — resolving "the current
  usable LLM client" is infrastructure's job, not a repository read.
- `broadcaster/telemetry/` + `broadcaster/infrared_record_session/` —
  gorilla/websocket fan-out. See [Websocket broadcaster
  pattern](#websocket-broadcaster-pattern) below.
- `logger/leveled/` — zerolog/slog dual backend behind
  `domaincontractslogger.Leveled`.

### Constructor & package naming convention

- Package names are `infrastructure<layer><feature>`, concatenated with no
  underscores (e.g. `infrastructurerepositorynode`,
  `infrastructureutilityencryption`, `infrastructurellmclient`). Directory
  names use `snake_case` (`repository/node_class_action/`,
  `llm/client_factory/`).
- Every swappable infrastructure adapter has an exported
  `New<Driver>Impl(...) domaincontracts<X>.<Interface>` constructor
  (`NewAESGCMImpl`, `NewGojaImpl`, `NewGorillaImpl`) that returns the
  **domain contract interface type**, never the concrete struct — so
  callers in `composition/` hold interface-typed fields, exactly like every
  other piece of swappable infra. The one exception is when the concrete
  type genuinely needs to be constructed with exported fields for tests in
  the same package (see `llm/client_factory/factory_test.go`'s struct
  literals) — even then, the public constructor itself still returns the
  interface.
- Repository interfaces use a fixed verb set:
  `Create`, `ReadById`, `ReadBy<Field>`, `ReadByPagination`, `UpdateById`,
  `DeleteById`. Do not introduce `Get`/`List`/`Find` — the whole repository
  layer was normalized onto the `Read*` family; new methods must match it.

## `internal/presentation/`

The only layer allowed to touch raw HTTP/MQTT request shapes.

- `http/handler/` — one package per resource area, Echo handlers. Handler
  methods are named `<Resource><Action>` (e.g. `PermissionPost`,
  `RoleGetList`, `LlmConfigTestConnectionPost`), matching the `AdminHandler`
  /`AuthHandler`/etc. interfaces declared in `http/route/route.go`.
- `http/request/`, `http/response/` — request DTOs and response shaping.
  Response types carry `example:"..."` swagger tags.
- `http/route/route.go` — every HTTP route registered in one place, each
  line reading `method, path, handler, permission("resource:action")`. See
  [Permission string convention](#permission-string-convention).
- `http/middleware/` — JWT auth + permission-checking middleware.
- `http/utils/` — raw-shape validation only (UUID/int/JSON parsing,
  presence checks) and the shared `Error(c, err)` responder — see
  [Error handling](#error-handling) and [Validation
  convention](#validation-convention).
- `http/proxy/` — reverse proxy to the Next.js frontend, plus a
  `/minio-proxy/*` proxy for presigned firmware downloads. The Go backend
  is the container's sole ingress; there is no nginx.
- `mqtt/handler/` — one file per MQTT topic concern (`registration.go`,
  `status.go`, `telemetry.go`, `ir_capture.go`, ...); `mqtt/dto/` and
  `mqtt/event/` hold the wire payload shapes and typed event structs.

## `internal/composition/`

Dependency wiring only — no business logic, no validation.

- `main/` wires the full HTTP+MQTT service:
  - `driver.go` — sets up Postgres/Redis/MinIO/MQTT clients and the Echo
    instance.
  - `infrastructure.go` — constructs every repository/cache/storage/
    broadcaster/utility adapter, held as domain-contract-typed fields.
  - `application.go` — constructs every usecase, wiring infrastructure
    fields into `New<Usecase>Impl(...)` constructors.
  - `presentation.go` — constructs handlers/proxies and registers routes.
  - `launcher.go` — `Launch() int`, the single process entrypoint.
- `seeder/` — a parallel, smaller composition for the one-shot seeder
  binary (Postgres only — no HTTP, Redis, or MQTT).

## `internal/config/`

All `BE_*` environment variables are declared as package-level `var`s in
`env.go` with a hardcoded default, loaded once via `config.LoadEnv()` at
process start. Never call `os.Getenv` outside this package — every other
package reads `config.SomeSetting` directly.

## `database/`

- `migrations/` — golang-migrate SQL, `YYYYMMDDHHMMSS_description.{up,down}.sql`.
  Time-series tables (`telemetry_records`, `action_logs`, `node_logs`)
  follow the existing TimescaleDB hypertable conventions: `BIGINT` identity,
  a composite primary key containing the time column, a 7-day chunk
  interval, no update/delete audit machinery, and down migrations that drop
  compression/retention policies before dropping the table/type.
- `seeder/` — baseline RBAC + example node class/action/user seed data as
  JSON, embedded into the seeder binary via `go:embed`, applied through raw
  Postgres repositories (not through the Redis cache layer — see [RBAC
  seed and cache rollout](#rbac-seed-and-cache-rollout)).

## `docs/`

- `swagger/` — generated by `swag init` (see [Regenerating swagger
  docs](#regenerating-swagger-docs)); never hand-edit `docs.go`,
  `swagger.json`, or `swagger.yaml`.
- `agent_test/<version>/` — a manual/scripted test checklist per release
  (`checklist.md` + one `scenario/NN-*.md` file per feature area), used to
  verify a build end-to-end against a real Postgres/Redis/MinIO/MQTT
  environment before release. Automated tests do not replace this for
  cross-boundary behavior.
- `releases/` — release notes.

## `pkg/pgxdt/`

A small standalone pgx transaction-context helper, deliberately outside
`internal/` so it's importable by other modules if ever needed.

# Code Rules

## Error handling

Every domain-level error is a sentinel declared in `domain/models/error.go`
as `ErrType<Name> = errors.New("SCREAMING_SNAKE_CASE")`, grouped by
existing category (generic: `ErrTypeNotFound`, `ErrTypeBadArgs`,
`ErrTypeConflict`, `ErrTypeValidation`, `ErrTypeForbidden`, ...; `*Exists`
sentinels for uniqueness violations; feature-specific ones like
`ErrTypeLlmConfigNotConfigured`, `ErrTypeBroadcastListenerLimitReached`).
Wrap one into a concrete error with
`domainmodels.NewError(message string, errType ErrorType, cause error) error`.
Surface it to HTTP with `presentationhttputils.Error(c, err)`, which walks
`presentationhttputils.errorMappings` (in `http/utils/error.go`) via
`errors.Is` to pick an HTTP status/title/message — add a new mapping row
there whenever you add a new `ErrType*` that should reach HTTP with
anything other than a generic 500. `Error.Is` is implemented so
`errors.Is(err, domainmodels.ErrTypeX)` works through wrapping.

Only add a new `ErrType*` when no existing one fits the failure's
*meaning* (not just its message) — reuse `ErrTypeConflict`/
`ErrTypeBadState`/etc. where the semantics genuinely match.

## Validation convention

Strict split between two kinds of validation:

- **Presentation** (`internal/presentation/http/utils/validation.go`) —
  raw request *shape* only: well-formed UUID, parseable int, valid JSON,
  non-empty. Closed wire enums may be rejected here too when an unknown
  token would otherwise reach a PostgreSQL enum and turn a client error
  into a 500 (the node-log level filter is the precedent). No business
  rules (length, charset) here.
- **Application** (`internal/application/shared/validation.go`) — every
  business rule about whether a *value* is acceptable (username
  charset/length, password strength, snake_case payload-schema names,
  node-class name charset, a payload schema definition's structural shape,
  a device_id's MAC format, ...) as paired `RequiredX`/`OptionalX`
  functions, called from each usecase's `Create`/`UpdateById` as the very
  first thing they do, before any repository or storage call.

When adding a new writable field anywhere in the API: presentation
parses/binds, application validates the value. Never validate business
rules in presentation, and never accept an unparsed raw shape in
application.

## Permission string convention

Every protected route's `permission(...)` argument is `"resource:action"`,
lowercase snake_case resource name matching the entity
(`node`, `node_class`, `payload_schema`, `llm_config`, `broadcast_session`,
`profile_security`) and mostly the closed CRUD vocabulary `get`, `add`,
`set`, `remove`, plus a couple of resource-specific verbs where CRUD
doesn't fit (`action:dispatch`, `ota:dispatch`). `infrared_record_session`
and `infrared_reference` use `delete` instead of `remove` for the same
concept — a pre-existing inconsistency, not a convention to copy; new
resources should use `remove`. Reuse an existing permission when the new
endpoint is
genuinely the same authorization boundary as an existing one (e.g. the new
`POST /admin/llm-config/test` endpoint reuses `llm_config:set` rather than
minting a new permission) — only add a new permission row (and seed it in
`database/seeder/`) when the authorization boundary is actually new.

## Websocket broadcaster pattern

`infrastructure/broadcaster/<domain>/` implementations (gorilla/websocket)
share one shape:

- A `client` struct wraps one `*websocket.Conn` with a buffered
  `send chan []byte`, a `writePump()` goroutine (drains the channel to the
  socket + periodic pings), and a `readPump(ctx)` (blocks reading incoming
  frames until error/close/ctx-done, then triggers cleanup).
- The broadcaster struct holds a `map[uuid.UUID]*client` guarded by
  `sync.RWMutex`.
- **Critical constraint**: once `websocket.Upgrader.Upgrade(w, r, nil)`
  succeeds, the HTTP response is fully committed to the websocket protocol
  — no failure after that point can be reported as a normal JSON HTTP
  error via `presentationhttputils.Error`. Any capacity/authorization check
  that needs to reject the request must happen strictly *before*
  `Upgrade` is called (see `broadcaster/infrared_record_session/gorilla.go`'s
  `reserve()` step, which claims the session's map slot under the mutex
  before ever calling `Upgrade` — the map is keyed by the domain id being
  broadcast to, e.g. `sessionId`, capping it to exactly one active listener
  per key).

## LLM client shape

`domaincontractsllm.Client` is intentionally *just*
`GenerateText(ctx, req) (result, error)` — no `Connect`/`Disconnect`/
`Status`. An earlier iteration added those three lifecycle methods, then
they were deliberately removed once `ClientFactory.Current(ctx)` took over
choosing the provider/model and returning an already-usable client — the
factory (not the client) is where connection/config concerns belong. Do
not re-add lifecycle methods to `Client` without a new explicit design
decision; if a provider adapter needs local state, put it behind the
factory, not the client contract.

## Naming and constructors (general)

- Usecase implementation packages: `application<area><usecase_name>`
  (e.g. `applicationadminusermanagement`), unexported struct named
  `usecase`, exported constructor `NewUsecaseImpl(deps...)
  domainusecases<area>.<Interface>`.
- Every usecase method starts with `const tag = "<area>/<usecase>/<Method>"`
  and passes `tag` plus `domainmodels.LoggerMeta{...}` into
  `u.logger.Error/Warn/Info(ctx, tag, message, meta)` on every failure path
  that reaches a boundary (HTTP response, MQTT ack) — logged failures must
  include enough metadata (ids, the underlying `err`) to diagnose without
  reproducing.
- Test doubles are named `fake<Thing>`/`stub<Thing>`/`recording<Thing>`,
  live in `_test.go` files in the same package as what they fake, and
  implement only the methods the current interface actually declares —
  delete stub methods immediately when an interface shrinks; don't leave
  dead methods "just in case".

## Automated-test convention

- Write tests against observable behavior and real package boundaries; small
  test-only fakes may record repository/logger/handler/middleware calls —
  keep them in `_test.go` files and assert the exact contract.
- For time-dependent fallback behavior, bound server time between values
  captured immediately before and after the call instead of asserting an
  exact timestamp.
- Route tests must exercise Echo registration with real requests so method,
  path, and permission strings can regress independently.
- Seeder tests decode the embedded JSON data and assert permissions/role
  grants as data — never grep source text for expected strings.
- Concurrency-sensitive code (broadcasters, anything with a mutex-guarded
  map) gets a test run under `go test -race`, not just a plain run.
- When a production error path requires logging, assert both error
  propagation and the logger metadata that makes the failure diagnosable.
- Older packages predate this convention and remain test-free; keep new
  behavior protected regardless.

## Node-log contract

- Firmware log lines have the exact shape
  `DD/MM/YYYY HH:MM:SS.mmm [LEVEL] [TAG] message`; the timestamp is UTC.
- Valid levels are exactly `NONE`, `ERROR`, `WARN`, `INFO`, `DEBUG`.
- Any syntax mismatch, impossible timestamp, out-of-range component, or
  unsupported level uses the full fallback: `NONE`, empty tag, the entire
  raw line as the message, and server receive time in UTC. Never drop
  malformed device logs.
- Keep parsing in the application layer; repository contracts accept only
  structured fields, never a redundant raw-line column.
- HTTP level filters reject unsupported values as validation errors before
  PostgreSQL ever sees the enum.

## Cross-layer fleet contracts

- Node `device_id` is the MQTT/device identity, immutable through the node
  update workflow. Changing it needs a deliberately designed identity
  migration, not an ordinary edit form.
- Persisted node and node-class names may contain safe underscores/hyphens
  (`node_<device-id>`, `base_node`); keep create/update validation
  compatible with those stored names while rejecting path-like/unsafe
  input.
- OTA dispatch accepts a `firmware_id`; the backend (not the browser) loads
  the authoritative node and firmware, checks node-class compatibility,
  resolves the firmware binary URL, and publishes authoritative
  checksum/size metadata. The route needs only `ota:dispatch` — don't add
  an accidental `firmware:get` dependency to the mutation.
- Firmware deletion requires the expected firmware name in the JSON
  request body, compared against the authoritative stored name
  server-side before deleting — the typed-name dialog is a safety
  interlock, not a source of truth.
- Firmware binary replacement distinguishes an omitted `config_schema`
  (preserve current schema) from an explicit empty array (clear it).
- String node-config values are stored verbatim, including empty or
  whitespace-only strings; validate presence separately from value
  content — numeric/boolean config types keep their own validation.
- Registration ack (`/sub/<device_id>/registration_ack`) always carries a
  real `{"success": bool}` body. `messaging_callback`'s `Register` usecase
  publishes exactly one ack per attempt via `defer` (`true` only on full
  success, `false` on any earlier failure) — on the firmware side,
  `success:false`, a missing `success` field, and an unparseable payload
  all restart the device immediately. Keep this in sync with
  `mate-espidf-base/AGENTS.md`'s MQTT protocol contracts.

## RBAC seed and cache rollout

`database/seeder/*.json` is written through raw Postgres repositories,
while effective user permissions are cached through Redis in the running
service. After adding/changing seeded permissions: validate the role
matrix in tests, and ensure deployment invalidates/increments the relevant
permission cache version (or restarts/clears the cache) before testing
with freshly issued authentication — a successful seeder run alone does
not prove cached authorization has refreshed.

# Development Flow

## Environment

Copy the repo-root `.env.example` to `.env` and fill in real credentials
for Postgres, Redis, MinIO, and an MQTT broker (HiveMQ Cloud in practice)
— none are bundled/started by this repo; they're expected to already
exist somewhere reachable. `BE_BASE_URL` must be the public URL the app is
served at (used to build presigned firmware-download links);
`BE_MQTT_CLIENT_ID` must be unique per running instance (a shared broker
kicks whichever client connects second with the same ID).

## Running locally

```bash
cd backend && go run ./cmd/main
```

Reads `BE_*` variables from the real environment (export them or use
`direnv`/`dotenv`). Always binds `:80` (hardcoded, not configurable) —
binding it without root/`CAP_NET_BIND_SERVICE` fails on most systems, so
running the raw binary outside Docker needs elevated privileges (e.g.
`sudo go run ./cmd/main`, or `sudo setcap 'cap_net_bind_service=+ep'` on
the built binary). See the repo-root `AGENTS.md` for the full Docker
Compose flow, which is the normal way to run everything together.

```bash
cd backend && go run ./cmd/seeder   # once, against a fresh DB, after migrations
```

Migrations use the `migrate` CLI directly against `database/migrations/`:

```bash
migrate -path backend/database/migrations -database "$DATABASE_URL" up
```

## Verification checklist for any backend change

1. ```bash
   cd backend && go test -count=1 ./... && go build ./... && go vet ./...
   ```
   All must pass. `gofmt -l .` and `git diff --check` must print nothing.
2. If the change touches a mutex-guarded map, a goroutine lifecycle, or any
   other shared-state concurrency, also run the affected package(s) with
   `go test -race`.
3. If any `@Success`/`@Param`/etc. swagger annotation changed, regenerate
   docs (below).
4. For anything touching HTTP/MQTT behavior end-to-end, build the Docker
   image and run it against the real `.env`-configured services, then
   exercise the change with `curl`/`mosquitto_pub`. Automated tests do not
   replace `docs/agent_test/<version>/` or a live-service integration
   check for cross-boundary behavior.

## Regenerating swagger docs

```bash
cd backend
swag init -g cmd/main/main.go -o docs/swagger --parseInternal --parseDependency
```

Run this after changing any handler's swagger annotations. The output
(`docs.go`, `swagger.json`, `swagger.yaml`) is generated — never hand-edit.

## Adding a migration

Create a new timestamp-prefixed pair in `database/migrations/`
(`YYYYMMDDHHMMSS_description.up.sql` / `.down.sql`), matching the existing
naming convention exactly so `migrate` orders them correctly. See
[Cross-layer fleet contracts](#cross-layer-fleet-contracts) and the
time-series conventions under [`database/`](#database) above for the
shape new tables should follow.

# Naming Note

The module path and most `BE_*` env defaults use `mate-things` /
`mate-things-backend`, but the swagger `@title` and several config
fallback defaults still say "Nusapala Things" / `nusapala-*` — an earlier
project name that was partially renamed. Both refer to the same project;
don't be surprised by the inconsistency, and prefer `mate-things` in
anything new.
